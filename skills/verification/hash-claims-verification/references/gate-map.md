# Gate-Map — OPEN vs CLOSED access paths (exercise the open ones)

Methodology for "investigate fully and explore possibilities with open gates".
Companion to hash-claims-verification rule 4 (ENUMERATE ACCESS PATHS) and the
blind-spot enumeration. The move beyond enumeration: classify each reachable
surface as OPEN (no credential you lack) or CLOSED (blocked on a cred/consent),
then ACT on the open gates to deliver value — don't just list and stop.

## Steps
1. PROBE EVERY surface live (curl http_code, redis PING, powershell Get-Service/
   Get-ScheduledTask, sqlite read). Never assume reachability from memory.
2. CLASSIFY: OPEN = HTTP 200 / reachable now / no-auth. CLOSED = 000|refused, or
   needs a credential you do NOT have. Record the live code as proof.
3. EXERCISE open gates concretely (proof + value, not just a ping):
   - If a local Ollama is OPEN (no-auth, 200), run a real generation through it.
     The ZQM SA briefing was generated by feeding live /sitrep JSON into N1
     qwen3:8b — that turned attestation into a narrative via a REAL open gate,
     zero credentials. (See C:\Users\zqmco\swarm\sitrep_narrative.md result.)
   - Use the exercise output as evidence the gate is genuinely usable.
4. ATTEST closed-but-exposed gates; do NOT exploit. A LAN-OPEN Ollama (46 models,
   200) is an exposure to report + gate-fix, not a resource to abuse. Listing
   models + confirming 200 is sufficient attestation; do not run bulk generations
   or pull models.
5. VERIFY newly-connected MCP backends before routing through them. The zqm-local
   MCP connected but its AnythingLLM backend returned WinError 10061 (refused) —
   that "local RAG" gate was CLOSED at that moment. Confirm the backend is up
   (curl its port) rather than assume a connected MCP server is usable. A local
   Ollama direct (OPEN) covered the need instead.
6. DELIVER a gate table: GATE | STATE | viable next action (cred-free) | blocked-by.
   Carry the GATE on every open gap so the SA is actionable.

## Cross-tool file trap (B17)
When a pipeline hands a file FROM an MSYS tool (curl, git-bash) TO a Win32 Python
interpreter, the MSYS-written file can be INVISIBLE to a plain `C:\...` path lookup.
RESOLVED with the Win32 long-path prefix `\\?\`: `open(r"\\?\C:\Users\zqmco\swarm\x.json")`.
If a Win32 Python `os.path.exists(r'C:\...')` mysteriously returns False on a file
curl just wrote, retry with `\\?\` before concluding it's missing. (Bit the
SA-narrative generator 3x this session; see hash-claims-verification → TRAPS.)
